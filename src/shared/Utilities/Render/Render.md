# Software Rasterization & Parallel Rendering Pipeline

## Classification & Domain Terminology
- **Domain:** Real-Time Software 3D Rasterizer & Graphics Engine
- **Subsystem:** Camera Matrix Projection, Guardband Frustum Clipping, Edge-Function Rasterization & Worker Parallelization
- **Raster Architecture:** Tile-Based / Parallel Actor Worker Rasterizer with 32-bit Floating-Point Z-Buffer (Depth Test)
- **Clipping Model:** 3D Camera-Space Sutherland-Hodgman Polygon Clipping

---

## Architectural Mechanisms

### 1. Camera Transformation & View Frustum
- **Single-Player OOP `CameraService` & `CameraMethods`**: `CameraService` provides an object-oriented camera abstraction (`CameraService.New`) and manages the active single-player camera singleton. It implements instance methods via `CameraMethods` (`SetCFrame`, `SetCameraView`, `SetCameraHost`, `ChangeFOV`, `ChangeSensitivity`, `GetCFrame`, `GetFOV`, `Destroy`).
- **Renderer-Side Camera Caching (`RenderService` & `RenderInstanceMethods`)**: `RenderService` caches the bound camera's orthonormal basis SIMD `vector`s (`CachedCameraPosVec`, `CachedCameraRightVec`, `CachedCameraUpVec`, `CachedCameraLookVec`) and projection scalars (`CachedFocalLength`, `CachedGuardBandX`, `CachedGuardBandY`) directly on the `RenderObject`, recomputing them only when `CameraCFrame`, `CameraFOV`, or viewport resolution changes—avoiding repeated OOP method calls on `CameraObject` during frame rendering.
- **Single-Player Input & Simulation Stepping (`CameraStepRunner`)**: Seeds from the simulated physics player position (`PhysicsController.GetPlayerPosition() + CameraPlayerEyeOffset`) or an explicit `Host` `BasePart`. Binds desktop mouse-look, `LeftAlt` mouse center lock toggle (`CameraMouseUnlockKey`), and unthrottled `PostSimulation` updates. On the client, `CameraStepRunner.LockWorkspaceCamera` locks `workspace.CurrentCamera` to `CameraFixedPosition` with matching orientation to avoid rendering default Roblox geometry.
- **Facades (`CameraStore` & `CameraLibrary`)**: `CameraStore` serves as a read-only data facade exposing the active camera's table and basis vectors to physics, player, and culling routines. `CameraLibrary` acts as the public consumer entry facade, re-exporting constructor (`New`), active singleton management, camera view controls, FOV updates, and CFrame/FOV getters.
- **`CameraHelper.VectorsToRotation`**: Generates an orthonormal orientation CFrame using view basis vectors (Look, Up, Right).
- **View Culling, Camera Collision & Observer Codec (`ViewCulling`, `ViewObserverCodec`, `CameraHelper`)**: `ViewCulling` performs fast radial and bounding-sphere tests plus an order-independent `PrepassDominantOccluder` pass (`UpdateClientView` / `UpdateObserverFromVectors`) without requiring a live `Head` `BasePart`. `ViewObserverCodec` encapsulates standalone observer candidate resolution, backward padding, and binary 56-byte observer state serialization. Camera occlusion resolves directly against the ECS `BVH.Raycast` acceleration structure (avoiding Workspace `RaycastParams` allocations).
- **Observer State Streaming Separation**: Periodic client virtual observer serialization and `ObserverStateEvent` network streaming live in `ReplicationReceiver.client.luau` / `ReplicationReceiverHelper.luau` on `Heartbeat`, completely decoupled from the render loop.

### 2. Guardband & Polygon Clipping
- **`MathModule.ClipPolygon` & `PolygonClipMath`**: Evaluates polygon vertices against camera frustum boundary planes using Sutherland-Hodgman clipping. `PolygonClipMath` provides focused frustum quad and triangle UV clipping and screen-space projection algorithms.
- Triangles intersecting the near plane are sliced dynamically into quads or clipped triangles, eliminating near-plane projection artifacts.

### 3. Mesh Registry & Perspective Projection (`VerticeFile`, `VerticeHelper`, `VerticeCurvedHelper`, `MathModule`, `RasterizerMath`)
- **`VerticeFile`, `VerticeHelper` & `VerticeCurvedHelper`**: `VerticeHelper` constructs procedural planar meshes (`BuildCubeMesh`, `BuildTriangleMesh`, `BuildPlaneMesh`) and coordinates `VerticeCurvedHelper` (`BuildSphereMesh`, `BuildCylinderMesh`) with winding-verified face normals; `VerticeFile` exposes shape ID/name translation (`IdToShape`, `ShapeToId`) and `ShapeData` lookup.
- **`MathModule.ProjectVertex` / `MathModule.ProjectVertexUV`**: Converts 3D camera-space coordinates into 2D viewport pixel coordinates with reciprocal depth ($1/Z$) and optional UV coordinates.
- **`MathModule.EdgeFunction` & `RasterizerMath`**: Computes signed 2D barycentric half-plane determinants for triangle traversal and pixel coverage testing. `RasterizerMath` provides exact scanline span edge clipping and bit-for-bit invariant sub-span rasterization across parallel worker bands.
- **Frustum OBB Reject & Sub-Span Perspective Rasterization (`RenderMath`, `RasterizerMath.RasterizeTriangleSpan`)**: `RenderMath.TransformShapeCameraVertices` early-rejects entire OBBs outside the camera-space X/Y guardband. Within `RasterizeTriangleSpan`, faces rasterize against worker scanline band bounds (`BandStartY..BandEndY`) using 8-pixel perspective-correct sub-spans (recomputing exact `(u, v)` every 8 pixels) and a fullbright white-tint fast path. Face `UAxisIndex` / `VAxisIndex` map world-space UV tiling (`TileScale`) per face orientation.
- **Depth Buffering:** Rejects occluded fragments via 32-bit floating-point Z-buffer comparisons inside each worker's local band before texture sampling.

### 4. Texture Management (`TextureTable`, `TextureHelper`, `ReplicationReceiverHelper`)
- **`TextureTable`**: Acts as the public texture directory (`Entries` hashmap), ID/name/URL translator (`IdToName`, `NameToId`, `IdToUrl`, `UrlToId`), deduplicated URL decoder (`DecodeRawUrl`, `RegisterUrl` ignoring duplicate URLs), and `64×64` RGBA `buffer` cache (`TextureTable.CachedBuffers[TextureId]`).
- **Workspace Decal Discovery (`ECSBuilderHelper`)**: Scans `Workspace` for `Decal` instances before populating parts, registers unique `Decal.Texture` URLs into `TextureTable.Entries`, syncs `TextureTable.Entries` to clients via `CoreEvents.TextureSyncEvent` for `64×64` decoding, and assigns matching `TextureId`s to parts.
- **Client Texture Sync Separation (`ReplicationReceiver.client.luau`, `ReplicationReceiverHelper.luau`)**: Client reception of `TextureSyncEvent` and background decoding into `TextureTable` live in `ReplicationReceiver.client.luau` and `ReplicationReceiverHelper.luau` inside the Controller Actor VM. `RenderController` simply tracks `TextureTable.GetVersion()` and broadcasts cached buffers to workers via `RenderWorkerGateway.BroadcastTextures` when versions advance.
- **ECS Bitfield Integration (`ECSMain`)**: Stores each entity's `TextureId` in bits `5..12` of the 32-bit `Properties` register, replicated to clients and read per-entity in `RenderController.DrawFrame` so different parts render with different cached `64×64` textures in the same frame.

### 5. Scanline-Band Parallel Worker Distribution & OOP Render Architecture
- **OOP `RenderService`, `RenderInstanceMethods` & `RenderResolutionHelper`**: `RenderService.New(Options)` treats `RenderConfig.RenderWidth` and `RenderConfig.RenderHeight` as pre-allocated maximum buffer ceilings so staged triangle, scanline work difference, and worker buffers are never invalidated when resolution scales down. Instance operations live in `RenderInstanceMethods` (`Init`, `DrawFrame`, `SetCamera`, `SetStorage`, `SetResolution`, `SetEnabled`, `GetScreenGui`, `GetImageLabel`, `GetEditableImage`, `Destroy`), while `RenderResolutionHelper` synchronizes active `(Width, Height)` from `ResourceController` / `ControllerInterpreter` and reports measured frame render times back to the closed-loop controller.
- **Self-Created Viewport GUI (`RenderWorkerGateway.CreateDisplayGui`)**: Rather than relying on external Roblox StarterGui instances, `RenderWorkerGateway.CreateDisplayGui` programmatically allocates and parents an inset-ignored, non-respawnable `ScreenGui` (`RendererScreenGui`) containing a full-screen `ImageLabel` (`ViewportLabel`) and an `AssetService`-created `EditableImage`. It also automatically disables legacy `ScreenGui` instances in `PlayerGui`.
- **Facades (`RenderController` & `RenderLibrary`)**: `RenderController` provides a singleton orchestrator maintaining the active `RenderService` instance, while `RenderLibrary` serves as the public unified API exposing constructors (`New`), singleton management (`GetActiveRenderer`, `SetActiveRenderer`), frame execution (`DrawFrame`), camera binding (`SetCamera`), and GUI accessors (`GetScreenGui`, `GetImageLabel`, `GetEditableImage`).
- **Unthrottled Non-Blocking Frame Dispatch (`RenderController.DrawFrame` / `RenderInstanceMethods.DrawFrame`)**: Executes unthrottled on `RenderStepped` whenever the previous parallel worker batch has completed (`ExpectedWorkers == 0` or all workers returned), preventing backpressure queue buildup across `Actor` VMs.
- **Dynamic Prefix-Sum Load Balancing (`WorkerPartitionHelper`, `RenderControllerHelper`)**: `RenderControllerHelper.SubmitFace` stages visible clipped 56-byte triangles once and records $O(1)$ scanline row cost deltas into `RowWorkDiff`. `WorkerPartitionHelper.PartitionWorkerBands` integrates cumulative row work (zeroing `RowWorkDiff` in-place), splits `[0..Height - 1]` into contiguous equal-cost horizontal worker bands (`BandStarts` / `BandEnds`), and `DispatchStagedTriangles` dispatches exact-sized command slices (`CompactSlice`) to overlapping `Actor` workers via `SendMessage`.
- **Worker Gateway & Parallel Ingestion (`RenderWorkerGateway`, `ParallelWorker.client.luau`)**: `RenderWorkerGateway` encapsulates `ScreenGui` / `EditableImage` creation, texture buffer broadcast, and parallel worker Actor message routing (`Execute Rendering`, `Return Render Calculations`). `ParallelWorker.client.luau` rasterizes only its assigned dynamic horizontal band (`BandStartY..BandEndY`) with local `ZBuffer` depth testing, clearing only previously dirtied local rows and returning a compact dirty-row pixel slice (`CompactSlice`) to `RenderService` for $O(\text{rows})$ compositing via `BufferHelper.CompositeWorkerBand`.

### 6. Client Render Cleaner & Descending-Size Culling ECS (`RendererCleaner.client.luau`, `CleanerHelper`, `CleanerSortHelper`)
- **Largest-First Culling ECS Ordering (`CleanerSortHelper`, `CleanerHelper.SyncRenderStorage`)**: Filters inactive, non-visible (`!ECSMain.IsEntityVisible`), and frustum/occluder-culled entities from `ObjectStorage`, computes each visible entity's non-negative surface-area size score (`ComputeEntitySizeScore`, handling both 3D solids and 2D planes), and populates `RenderECSStorage` densely in slots `1..VisibleCount` ordered strictly from **biggest part (slot 1) to smallest part** with deterministic `ObjectId` tie-breaking.
- **Zero-Allocation In-Place Sorting**: Tracks monotonic order during the gather scan to skip the sort pass when already ordered, and otherwise sorts in place over pre-allocated `SortedSizes` / `SortedObjectIds` buffers via iterative median-of-three Quicksort (bounded `SortStack`) with an insertion-sort cutoff (`< 20` entries).
- **Incremental Slot Synchronization**: Maintains bidirectional `RenderSlotByObjectId` and `ObjectIdByRenderSlot` buffers, copying component slices only when a render slot's assigned `ObjectId` changes or `DirtyFlags` indicate source mutations, and zeroing vacated trailing slots when `VisibleCount` shrinks.
